# PRD: frontier-wire (репозиторий-издание) + ADanMan.github.io (сайт-резюме) + рутины

Дата: 2026-09-03. Автор запроса: Danila Katalshov (ADanMan). Исполнитель: Claude Code.

## 1. Введение

Два новых публичных продукта по образцу работающего `ADanMan/agentic-frontier`:

1. **`ADanMan/frontier-wire`** — репозиторий-«новостное издание» широкого профиля
   (не персональный лог): облачная рутина 2 раза в день собирает дайджест из
   тысяч источников, отбирает самое интересное и публикует выпуски (RU+EN).
   README ведёт себя как «первая полоса» и обновляется каждым выпуском;
   `feeds.txt` пополняется/чистится автоматически (скилл по мотивам OpenPlanter).
   Сайт издания: **adanman.github.io/frontier-wire** (GitHub Pages из `docs/`).
   Позже возможен перенос на отдельную организацию → `frontier-wire.github.io`
   (создание организации остаётся за пользователем). На сайте — ссылка на автора
   (adanman.github.io, LinkedIn, t.me/adanman).

2. **`ADanMan/ADanMan.github.io`** (репо уже существует, пустое) — персональный
   сайт: резюме (из PDF пользователя) + лента персональных публикаций из
   `agentic-frontier` (posts / til / guides), перегенерируемая рутиной.

Дизайн обоих: единая неопруталистская система, палитра **жёлтый / розовый /
чёрный**; референсы — styles.refero.design, checklist.design,
generativeloaders.com, jakubkrehel/skills. Чистый HTML+CSS+минимальный JS,
без сборщиков и фреймворков.

## 2. Цели

- Полностью автоматическое издание: ни один выпуск не требует ручных действий.
- Выпуски grounded: каждый материал ссылается на реальный источник дня.
- Оба сайта живут на GitHub Pages и обновляются пушами рутин.
- Тексты «человеческие»: пишущие скиллы (humanizer, bait-headlines и опыт
  рутины agentic-frontier) зашиты в промпты рутин.
- Репозитории «красивые»: README как продукт, аккуратная структура, лицензия.

## 3. User stories

### US-001: Репозиторий frontier-wire
Как читатель, я открываю README и вижу свежую «первую полосу»: заголовки
сегодняшнего выпуска со ссылками, архив выпусков, описание, как это работает.

**Acceptance criteria:**
- [ ] Публичный репо `ADanMan/frontier-wire` с MIT-лицензией
- [ ] Структура: `README.md`, `feeds.txt`, `editions/YYYY/MM-DD/`, `scripts/digest.py`, `scripts/build_site.py`, `docs/`, `.claude/skills/feed-gardener/`
- [ ] README содержит блок «сегодняшний выпуск», обновляемый рутиной, и честное описание автоматизации (как в agentic-frontier)

### US-002: Дайджест «всё-всё-всё»
Как рутина, я запускаю `digest.py` и получаю сводку из широкого набора
источников без тематического фильтра (tech, наука, культура, мир).

**Acceptance criteria:**
- [ ] `digest.py` читает `feeds.txt` (RSS/Atom), терпит мёртвые фиды, кэпит объём
- [ ] `feeds.txt`: зеркала на raw.githubusercontent.com первыми (доступны из sandbox облачной рутины), открытые источники ниже
- [ ] Локальный запуск `python3 scripts/digest.py` отрабатывает без ключей

### US-003: Выпуск издания
Как читатель, я открываю `editions/2026/09-03/` и вижу выпуск: обложку-оглавление
и статьи по рубрикам (AI / Tech / Science / World / Culture), RU+EN, со ссылками
на источники.

**Acceptance criteria:**
- [ ] Формат выпуска задокументирован (index.md + NN-slug.md)
- [ ] Есть хотя бы один реальный выпуск, собранный при создании репо

### US-004: Скилл feed-gardener
Как рутина, раз в неделю я ищу новые источники и чищу мёртвые в `feeds.txt`
(идея OpenPlanter: расширение сада источников).

**Acceptance criteria:**
- [ ] `.claude/skills/feed-gardener/SKILL.md` с процедурой: проверить живость фидов, найти кандидатов, добавить с комментарием, не ломать порядок «зеркала первыми»

### US-005: Сайт издания
Как читатель, я открываю adanman.github.io/frontier-wire и вижу газетный сайт:
первая полоса, архив выпусков, страницы статей, переключатель RU/EN.

**Acceptance criteria:**
- [ ] `build_site.py` рендерит editions → `docs/` (статический HTML)
- [ ] GitHub Pages включён (main, /docs), сайт открывается
- [ ] Неопрутализм, жёлтый/розовый/чёрный; CSS-лоадер (generativeloaders) на переключении языка/архиве
- [ ] В шапке/подвале ссылка на автора: adanman.github.io, LinkedIn, Telegram
- [ ] Проверка в браузере (desktop + mobile viewport)

### US-006: Персональный сайт ADanMan.github.io
Как посетитель, я вижу резюме Данилы (на основе двух PDF: строит платформу
агентских рабочих мест в beeline cloud, ex-Tech Lead MWS AI, преподаёт в ВШЭ/МИФИ/ЮФУ,
публикации AVI/MDPI, TACC, образование МГТУ) и ленту его публикаций из
agentic-frontier.

**Acceptance criteria:**
- [ ] Деплой в существующий пустой репо `ADanMan/ADanMan.github.io`, Pages с корня
- [ ] Резюме RU+EN, контакты: katalshovd@gmail.com, t.me/adanman, LinkedIn
- [ ] `scripts/build_site.py` тянет posts/til/guides из agentic-frontier (raw.githubusercontent — работает и в sandbox) и рендерит HTML-страницы
- [ ] Та же дизайн-система, что у frontier-wire, но «персональный» характер
- [ ] Проверка в браузере (desktop + mobile viewport)

### US-007: Рутина frontier-wire editor
Как владелец, я не трогаю репо: облачная рутина 2×/день делает
digest → пишет выпуск → обновляет README → build_site → commit+push;
раз в неделю утром дополнительно запускает feed-gardener.

**Acceptance criteria:**
- [ ] Рутина создана через schedule (cloud), расписание ~07:00 и ~19:00 MSK
- [ ] Промпт рутины включает пишущие гайдлайны: humanizer-принципы (без AI-штампов), bait-headlines для заголовков, тон и структура — по опыту рутины agentic-frontier
- [ ] Один ручной тестовый прогон прошёл: выпуск закоммичен, сайт обновился

### US-008: Рутина personal-site refresh
Как владелец, я получаю на adanman.github.io свежие публикации: отдельная
рутина 1×/день (после утренней рутины agentic-frontier) перегенерирует ленту.

**Acceptance criteria:**
- [ ] Отдельная облачная рутина (пользователь подтвердил: «норм и отдельную»)
- [ ] Один ручной тестовый прогон прошёл

## 4. Функциональные требования

- FR-1: Оба репо публичные, у обоих включён GitHub Pages.
- FR-2: Все скрипты — Python 3 stdlib (без pip-зависимостей), как digest.py в agentic-frontier.
- FR-3: Выпуски и посты двуязычные RU+EN в одном файле (секции), как принято в agentic-frontier.
- FR-4: Рутины работают в облачном sandbox, где сеть ограничена raw.githubusercontent.com — вся критичная загрузка данных строится на этом.
- FR-5: README frontier-wire обновляется каждым выпуском (свежие заголовки + ссылка на сайт + архив).
- FR-6: Сайты статические, ссылки относительные (учёт base path /frontier-wire/).

## 5. Не входит (non-goals)

- Никаких бэкендов, БД, комментариев, аналитики, рассылок.
- Не создаём GitHub-организацию frontier-wire (пользователь сделает сам при желании; репо переносится без потерь).
- Не трогаем существующую рутину agentic-frontier.
- Кастомные домены — вне скоупа.

## 6. Дизайн

- Стиль: неопрутализм (жирные чёрные рамки, оффсет-тени, крупная типографика, жёлтые/розовые плашки на светлом фоне; тёмная тема — опционально позже).
- frontier-wire = «газета»: mast-head, рубрики колонками, номера выпусков.
- ADanMan.github.io = «персональная полоса»: hero-резюме, карточки опыта, лента публикаций.
- Кросс-ссылки: издание ↔ автор.
- Финальный прогон страниц по чек-листам checklist.design (мета, favicon, 404, контраст, alt).

## 7. Технические замечания

- Прототип пайплайна — `agentic-frontier/scripts/digest.py`; форкаем и обобщаем.
- Markdown→HTML: минимальный конвертер на Python stdlib — без внешних пакетов, чтобы рутина в sandbox не зависела от pip.
- Push из рутины — той же схемой, что у agentic-frontier (git с токеном окружения рутины).

## 8. Метрики успеха

- 3 дня подряд рутины публикуют без ручного вмешательства.
- Оба сайта открываются и корректно выглядят на мобильном.
- README frontier-wire всегда показывает выпуск не старше 24 часов.

## 9. Открытые вопросы

- Точные слоты расписания (беру 07:00/19:00 MSK, поправим по факту).
- Набор зеркал для не-tech тем в sandbox — что реально доступно на raw.githubusercontent, выяснится при наполнении feeds.txt; открытые источники добавим сразу, они работают при открытой сети.
